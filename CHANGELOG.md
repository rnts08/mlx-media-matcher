# Changelog

media-match uses semantic versioning, tuned to how the tool actually grows:

- **major** — reserved for breaking changes to the CLI or the index format.
- **minor** — a large change in operations or functionality. `0.1.0` was the
  image-only tool; `0.2.0` added video indexing with the same machinery.
- **patch** — every feature or fix inside one era. New functionality lands as
  its own commit and bumps the patch number.

The entries below were recorded retroactively so the numbering reads
naturally against the work that produced it.

## 0.3.x — folder consolidation

- **0.3.0** feat: `folders` — find folders that share a name regardless of case (`2019/christmas`, `2020/Christmas`, `2021/CHRISTMAS`) and work on them at the folder level, the counterpart to `duplicates`/`clean` for the mess that exports and phone backups leave one directory up. Discovery is recursive and case-insensitive (the `find -iname` filter, with `--name` narrowing what counts), never follows directory symlinks, and respects hidden directories and `.media-matchignore`. The default is an interactive review: the shallowest copy is suggested as the destination, then every same-relative-path file conflict is decided with `r`/`R` replace, `n`/`N` rename (the incoming file becomes `photo_1.jpg`), `s`/`S` skip, `c` compare (size, mtime, image EXIF, video facts) and `q`/`Esc` quit; the capital keys apply to every remaining conflict in the run. Decisions are buffered per source folder, so nothing moves until the final confirmation, and quitting asks whether to execute the folders already finished while excluding the open one. `--replace`/`--rename` set the conflict policy up front, `--yes` uses the suggested destination and applies without prompts (skipping conflicts unless a policy is given — "yes to everything" must not guess between overwrite and duplicate), `--dry-run` prints the plan and writes nothing, `--json` reports for `--list` and `--dry-run`. `--collapse` is the non-destructive sibling: it keeps the destination in place and gathers every other member into `<root>/<Name>_collapsed/` as `<Name>_1`, `<Name>_2`, … without touching the files inside, continuing the numbering on a second run. Empty source folders and the parents they leave behind are removed; folders with skipped files stay. Tree-shape disagreements (a file where the destination has a folder) are reported and skipped rather than forced, folders nested inside their own destination are refused, and a failed move is reported without stopping the rest. Planning reserves destination paths across sources, so two sources with the same filename cannot both aim at `same_1.txt`. Filesystem-only: no index is read or written; the command says so and points at `scan --prune`. The design record, including the raw request and the ticket breakdown, is `docs/FEATURE-folder-consolidation.md`.

## 0.2.x — video support

- **0.2.28** feat: live progress for `describe`, the stage that needed it most and had the plainest output. It was the only long-running pass still printing `[n/total] describing ...` lines, one per item, at roughly a second per item — the slowest stage in the tool and the one where an idle GPU is hardest to see. It now draws the same two-line bar as `scan` and `analyze`: completion, rate and ETA, the names of the frames being decoded, CPU-seconds, and GPU-seconds as a share of wall time. The buffer counter reads `window 6/8` rather than `ring 1.0GB/1.0GB`, because describe's prefetch queue is measured in frames: full means the caption model is the bottleneck and `--describe-workers` will not help, empty means it is waiting on decodes and it will. Fixed alongside it: rates under 10/s were rounded to whole numbers, so a working describe stage spent its whole run displaying `0/s`, which reads as stuck rather than slow.
- **0.2.27** doc: `--exact-phash` now says it ignores `--threshold` rather than "faster than general threshold" - the flag groups only distance-0 matches and never consults the threshold, which a reader combining the two would otherwise not discover. README notes that videos need ffmpeg/ffprobe and that an unreadable video is reported with ffmpeg's own reason.
- **0.2.26** fix: two undefined-name crashes, both found by running the real commands on real media. `_prepare_bytes` had lost its `from PIL import Image` when the image branch moved to `load_image_tolerant`, so **every video** failed with `NameError` on `Image.fromarray` — a video library indexed as `analyzed 0, errors 291` after hours spent decoding frames that were then discarded. `find_duplicate_groups` appended to a `groups` list declared further down the function, so `--exact-phash` raised `UnboundLocalError` on every call; its reject list was also sorted by a loop variable leaked from a comprehension, and it fell through to the Hamming pass after grouping, which would have reported the same files twice. Added an AST lint test for undefined names across the package — the bug class that broke both — plus regression tests for staged video indexing and for `--exact-phash`. fix(cli): `_diagnose_failure` ran the *image* diagnosis on any failed path, so a video failing on ffmpeg or on a missing import was reported as "Pillow cannot identify or decode this file": true, useless, and the reason the real error stayed hidden.
- **0.2.25** feat(docs): `media-match help` now groups commands by what they are for instead of listing them alphabetically — get oriented, build the index, go deeper, find things, quality and file management, metadata, index maintenance. An alphabetical list answers "what is this called?"; the grouping answers "what do I want?", and reads in the order you would actually reach for the commands. The README's commands table is grouped to match. `main()` refuses to start if a command is missing from the grouping, listed twice (which is how `check` and `export` were ambiguous in the first draft), or named by a group that does not exist. doc: `about`, `info`, `version` and `restore` were never given a row in the README commands table at all.
- **0.2.24** feat: live progress bar for `scan`/`analyze`/`describe`, replacing the periodic "preparing [n/total]" lines on a terminal. Shows the names of the files in flight, how full the read ring buffer is, CPU-seconds across all threads, and GPU-seconds as a percentage of wall time — enough to tell a slow disk from an idle GPU from a GIL-bound CPU stage without attaching a profiler. Rendered on its own thread at 10 Hz so instrumentation never sits in front of a decode; the pipeline only mutates a small state object under a lock. `--no-progress` (or `MEDIA_MATCH_NO_PROGRESS=1`) disables it; it is off automatically when stderr is not a terminal, so piped output and CI keep one-event-per-line logs. fix(cli): `search --limit` and `tags --limit` had no help text and rendered as a bare "(default: 50)"; `_flag_lines` also produced ragged triple-spaced gaps for help strings ending in a space. fix(pipeline): `run_staged_scan` never incremented `ScanStats.bytes_read` — only the older `run_scan` did — so `stats` had reported `0.0B read` for every scan since the staged pipeline shipped.
- **0.2.23** feat: `about bench` — measures this machine and recommends `--batch`/`--io-workers`/`--workers`. Times disk reads, CPU decoding and CLIP batches in isolation, then runs several real configurations end to end through `run_staged_scan` and reports throughput plus the share of wall time in the GPU, with a projection onto the real tree size. Defaults to a deterministic synthetic corpus (no photos needed, comparable between runs and machines); pass a folder to benchmark real media. Nothing is indexed and no file is touched. The recommendation is deliberately conservative: configurations within the measured run-to-run spread (~10% on a small corpus) are reported as tied and the cheapest of them is recommended, because picking the nominal winner would present a coin flip as a measurement.
- **0.2.22** fix(cli): stop Pillow's warnings reaching the user. Truncated reads, malformed MPO containers and decompression-bomb guard hits printed a `site-packages/PIL/...` path with no filename, once per file — noise in a scan of thousands of files and useless without knowing which file was affected. New `diagnose` module captures them and turns each into a per-file explanation; `scan`/`analyze` now report the filename and what is wrong with it, grouped by cause, with a pointer to `media-match check`. `check` gained a fourth category, `notable` (loads fine, e.g. an MPO read as plain JPEG, or a 121 MP image) — reported but never repaired, so a perfectly good photo is not sent to quarantine. perf(pipeline): three data races in the staged scan that lost or duplicated work silently — every reader thread walked the whole job list (so `--io-workers 4` indexed everything 4×), each reader closed the ring buffer in its own `finally` (so the first to finish closed it under the others), and the GPU loop stopped when readers finished rather than when CPU workers were done (dropping results mid-decode). Termination now keys off per-worker sentinels on the batch queue. fix(pipeline): the staged pipeline decoded images with a bare `Image.open` and silently dropped every truncated file, which the sequential path had always indexed; both now share `load_image_tolerant`.
- **0.2.21** perf(cli): ring-buffer scan pipeline — reader threads fill a bounded ~1 GB `RingBuffer`, CPU workers decode/hash/preprocess, one GPU stage batches CLIP embeddings, one writer stores; disk I/O, CPU and GPU overlap instead of running in sequence (`--io-workers` sizes the reader pool). VLM batching via `Describer.describe_batch()` with `--describe-batch N` (default 1) so captions cost one forward pass per N frames. feat: `bootstrap --move-to DIR` moves non-media files to a folder — keeping their layout, never overwriting an existing file — instead of trashing them. fix(cli): `run_staged_scan` was called but never imported, so every `scan`/`analyze` run raised `NameError`. fix(cli): `analyze`, `describe`, `check`, `reset`, `bootstrap`, `clear-metadata`, `import-metadata` and `export-metadata` were missing from the help registry, so `help <cmd>` answered "Unknown command"; `<cmd> help` treated "help" as the root path and crashed opening a database in a folder that did not exist. feat(cli): `<cmd> --help` now prints the same page as `<cmd> help` and `help <cmd>` — previously it was a bare argparse option dump without the description or example; eleven commands had no description at all and now have one.
- **0.2.20** feat: `analyze` — one integrated pass (scan + describe + refine + classify) over images and videos with a GPU-fed pipeline; `describe` command; `clear-metadata`/`import-metadata`/`export-metadata` round-trip; `reset` command; `check` command (classify ok/truncated/corrupt, interactive repair); `bootstrap` command (dry-run first pass; `--prune`/`--media-only`/`--fix-extensions`); extension consolidation rolled into `bootstrap --media-only`; fix `--describe` without `--model` failing every caption with `Path(None)`; scan tolerates truncated images; periodic MLX cache release on long runs
