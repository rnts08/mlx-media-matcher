# Changelog

media-match uses semantic versioning, tuned to how the tool actually grows:

- **major** — reserved for breaking changes to the CLI or the index format.
- **minor** — a large change in operations or functionality. `0.1.0` was the
  image-only tool; `0.2.0` added video indexing with the same machinery.
- **patch** — every feature or fix inside one era. New functionality lands as
  its own commit and bumps the patch number.

The entries below were recorded retroactively so the numbering reads
naturally against the work that produced it.

## 0.4.x — quick index and id windows

- **0.4.5** feat: `analyze` is now the complete pass its description always promised. Indexing runs first, then every undescribed item is captioned, missing CLIP embeddings are filled in, every untyped image is classified, and captions/keywords are refined into canonical tags/facets — no stage flags needed. `--describe`/`--refine`/`--classify` are accepted silently for 0.4.x compatibility but no longer select stages; use `scan` when only the index (pHash, exact duplicates, folder cleanup) is wanted, or `describe`/`classify`/`refine` for one stage at a time. feat: standalone `classify` command — type indexed images with zero-shot CLIP without recaptioning or re-embedding, with `--recompute` and the usual id window. feat: `bootstrap` now folds in `check`: after inventorying it reports ok/truncated/corrupt/notable files and offers the same re-encode/quarantine repairs (prompted in a terminal; `--yes` applies them), then refreshes the bootstrap table if anything changed; `--no-check`, `--quarantine` and `--no-progress` control it. feat: `refine` (and `scan --refine`/`--classify`) now says `describe` is required instead of silently producing no tags when the index has no captions; `scan --describe --refine` was reordered so the captions exist before refinement. docs: `scan` help leads with what it indexes (size, dimensions, capture date, pHash, CLIP) and states that pHash is only computed for new files or files changed since bootstrap; the README workflow is now bootstrap -> scan -> analyze, and the command table documents `classify` and the folded-in check. 386 passed, 1 skipped.

- **0.4.4** fix(docs): `analyze` was described as "one integrated pass: scan, describe, refine and classify", but only indexing happens by default — captions, tags and types are opted into with `--describe`, `--refine` and `--classify`. A plain `analyze` over 13k files finished with `described 0, refined 0, classified 0` and looked like a failure. The summary now reads "scan, plus optional captions, tags and types in one pass", and the command page and README say outright that without those flags it does the indexing work of `scan`. `embed` is now "fill in missing CLIP embeddings for indexed images" (and says videos are embedded by `scan --video`), `describe` uses "caption" consistently, and the "go deeper" group names embeddings alongside captions, tags, types and people. `search`'s long help also disagreed with its behaviour: it claimed captions/tags by default, while words use CLIP whenever embeddings exist and `--fts` selects full-text captions/tags. 2 help tests (374 passed, 1 skipped).

- **0.4.3** fix: the live progress bar was never actually visible. Its two lines were joined with a bare `\r` and every frame ended with clear-to-end-of-line, so each redraw erased both lines before the terminal could show them: the scan ran with no output at all. `ProgressBar.draw` now moves back up over the previous block and clears/rewrites each line, leaving the cursor below it; `stop` no longer appends a stray blank line, and a renderer whose writes fail disables itself and is reaped instead of waking forever. The no-bar fallback is armed even when the bar starts enabled, so a terminal that cannot encode the block characters gets the 10-second heartbeat (ASCII-safe) rather than silence. fix: scanning a video larger than the 1 GB read ring deadlocked the whole pipeline. `RingBuffer.put` waited while `buffered + size > capacity`, a condition that can never become false when one file is bigger than the buffer; the index showed 1.5 GB, 1.5 GB and 1.2 GB clips among the 1,010 videos still waiting, while 368 had been analysed before the hang. An oversized item is now allowed through when the buffer is empty, so it becomes the one item in flight instead of blocking the only reader, every CPU worker and the main loop. perf: the staged scan no longer reads videos into memory or writes a temp copy for ffmpeg — the reader queues the path, the CPU worker streams the SHA1 in 1 MiB chunks and ffprobe/ffmpeg read the original file, removing 1.5 GB of RAM per big clip and two of the three passes over it. 6 new tests (372 passed, 1 skipped).

- **0.4.2** fix: a scan no longer goes silent. The CLIP weights were loaded lazily inside the first GPU batch, so the first-run Hugging Face download bars appeared in the middle of the scan, could overwrite the scan's progress bar, and the weight load itself looked like a hang; the weights now load as an announced step before the bar starts (`loading <model> (first run downloads it) ...`, then `model ready in 0.9s`), and `describe` does the same for the caption model. The no-bar fallback (piped logs, CI, `--no-progress`) now prints `indexing 0/N starting ...`, keeps its 5% lines, and adds a 10-second heartbeat naming the file being read or decoded — or `embedding` while a GPU batch is in flight — so with 13k jobs a single slow video can no longer leave the screen blank for minutes; the live bar also says `embedding` instead of `idle` during a GPU batch. perf: `run_staged_scan` found each item's `ScanJob` by walking the whole job list (`next((j for j in jobs ...))`), which is quadratic and made a 13k-file rescan spend a long time before the first stored result; it now uses a path→job dict built once. 4 new tests (366 passed, 1 skipped).

- **0.4.1** fix: user mistakes answer with one line instead of a stack trace. `media-match scan hekp` used to die inside sqlite3 with `sqlite3.OperationalError: unable to open database file`, because every command that creates or walks the tree opened `<root>/.media-match.db` before checking that the root exists. `scan`, `analyze`, `check`, `bootstrap` and `about bench` (and `folders`, which already checked) now share one `_require_root` helper and answer `No folder at <path>.` on stderr with status 2 — including when the root is an existing file, and moving `folders`' message there too so no failure pollutes stdout. Second line of defence: `main()` dispatches through a net (`_run_command`) that converts the errors a user can cause into messages: a `--db` in a nonexistent folder or a file that is not a database prints `cannot open the index database at <path>: <sqlite's reason>` and exits 2, any other escaping `OSError` (e.g. `export --out` into a missing directory) prints `<reason>: <path>` and exits 1, and Ctrl-C exits 130 with `Interrupted.` like `folders` already did. Unknown commands and unknown flags were already argparse's own one-liners (exit 2). Only the expected user-input failures are caught — a constraint or programming error still raises its traceback as the bug it is. Every failure message now goes to stderr so `--json` stdout stays parseable: besides the new messages, that moved the 15 "No index at <path> — run 'media-match scan' first." notices (which `stats --json` used to print on stdout), the folders/clean/restore/reset aborts, import errors and the "run scan/embed/refine first" hints. "No matches." stays on stdout because it is a search result, like grep's. 16 tests in `tests/test_cli_errors.py`.

- **0.4.0** feat: `scan --quick` — a stat-only first pass that gives every media file an index row and a stable id without reading file contents: no SHA1, no decode, no EXIF, no pHash, no CLIP, no ffprobe (so `--video` needs nothing installed). Basic rows carry path/size/mtime and empty hashes; `ON CONFLICT(path) DO NOTHING` means a quick pass can never downgrade an analysed row, and a changed file is left for a normal scan to notice through size/mtime. `--limit N` inserts at most N *new* rows, so repeated runs advance through the tree instead of repeating the first N files; `--prune` still reconciles the whole index; `--describe`/`--refine`/`--classify`/`--reanalyze` and id windows are refused (`--quick` creates the rows, it does not consume them). A normal `scan` treats `sha1 = ''` as incomplete and queues the row even when size and mtime already match, preserving any caption a quick row had picked up. Because basic rows would otherwise look byte-identical to each other, duplicate grouping now ignores rows with an empty SHA1/pHash (images) or SHA1/keyframes (videos) — without that guard, `duplicates`/`clean` run right after `--quick` would group every unanalysed file together. The second half is an inclusive id window, `--start-id`/`--stop-id` (aliases `--startid`/`--stopid`), on every command that selects media rows: `scan`, `analyze`, `describe`, `embed`, `refine`, `search` (FTS, CLIP, `--type`, `--cluster`), `similar`, `duplicates`, `clean`, `export`, `export-metadata`, `import-metadata` and `clear-metadata`. `files.id` and `videos.id` are independent sequences and the same numeric window applies to each; rows outside the window are never touched, and a window selects indexed rows only — new files are not scanned, which is why `--quick` exists. With `--start-id`, scan/analyze load rows in id order and `--limit` caps the window, so `--start-id 1001 --limit 1000` is the next slice and `--start-id 353 --stop-id 905` is exactly that range; `--prune` stays index-wide with a note when both are given. Refine's tag deletion is scoped to the ids the run rebuilds (also fixing a latent bug that wiped every tag of a kind when nothing was refinable), explicit paths outside the window in `clear-metadata`/`import-metadata` are reported as `outside id window:` and skipped, and non-positive ids or an inverted window exit 2. Deliberately window-less: `restore` (trash batches), `bootstrap` (its own re-numbered table), `people` (rebuilding clusters partially would erase the rest) and the aggregates `tags`/`stats`/`info`. Fixed alongside: `duplicates --video` computed video groups and then overwrote them with image groups. 26 new tests in `tests/test_quick_index.py`; the design record, including the raw request, is `docs/FEATURE-quick-index-and-id-ranges.md`.

## 0.3.x — folder consolidation

- **0.3.0** feat: `folders` — find folders that share a name regardless of case (`2019/christmas`, `2020/Christmas`, `2021/CHRISTMAS`) and work on them at the folder level, the counterpart to `duplicates`/`clean` for the mess that exports and phone backups leave one directory up. Discovery is recursive and case-insensitive (the `find -iname` filter, with `--name` narrowing what counts), never follows directory symlinks, and respects hidden directories and `.media-matchignore`. The default is an interactive review: the shallowest copy is suggested as the destination, then every same-relative-path file conflict is decided with `r`/`R` replace, `n`/`N` rename (the incoming file becomes `photo_1.jpg`), `s`/`S` skip, `c` compare (size, mtime, image EXIF, video facts) and `q`/`Esc` quit; the capital keys apply to every remaining conflict in the run. Decisions are buffered per source folder, so nothing moves until the final confirmation, and quitting asks whether to execute the folders already finished while excluding the open one. `--replace`/`--rename` set the conflict policy up front, `--yes` uses the suggested destination and applies without prompts (skipping conflicts unless a policy is given — "yes to everything" must not guess between overwrite and duplicate), `--dry-run` prints the plan and writes nothing, `--json` reports for `--list`, `--collapse` and `--dry-run`. `--collapse` is the non-destructive sibling: it keeps the destination in place and gathers every other member into `<root>/<Name>_collapsed/` as `<Name>_1`, `<Name>_2`, … without touching the files inside, continuing the numbering on a second run. Empty source folders and the parents they leave behind are removed; folders with skipped files stay. Tree-shape disagreements (a file where the destination has a folder) are named and skipped rather than forced, nested members and folders nested inside their own destination are refused, and a failed move is reported with its OS reason without stopping the rest. Each conflict prompt shows both sides' size and modification time. Failure modes are explicit: discovery is all-or-nothing, so an unreadable directory is named and the command exits 1 without changing anything; a source that cannot be read while planning is discarded whole and left untouched; declining a confirmation prints `Aborted; nothing was changed.` and exits 1; EOF acts as quit; `Ctrl-C` exits 130 (before execution nothing has moved, during execution the lines above say what did). Planning reserves destination paths across sources, so two sources with the same filename cannot both aim at `same_1.txt`. Filesystem-only: no index is read or written; when an index file does exist the command says it is now stale and points at `scan --prune` (including `--db` when one was given). The design record, including the raw request and the ticket breakdown, is `docs/FEATURE-folder-consolidation.md`.

## 0.2.x — video support

- **0.2.28** feat: live progress for `describe`, the stage that needed it most and had the plainest output. It was the only long-running pass still printing `[n/total] describing ...` lines, one per item, at roughly a second per item — the slowest stage in the tool and the one where an idle GPU is hardest to see. It now draws the same two-line bar as `scan` and `analyze`: completion, rate and ETA, the names of the frames being decoded, CPU-seconds, and GPU-seconds as a share of wall time. The buffer counter reads `window 6/8` rather than `ring 1.0GB/1.0GB`, because describe's prefetch queue is measured in frames: full means the caption model is the bottleneck and `--describe-workers` will not help, empty means it is waiting on decodes and it will. Fixed alongside it: rates under 10/s were rounded to whole numbers, so a working describe stage spent its whole run displaying `0/s`, which reads as stuck rather than slow.
- **0.2.27** doc: `--exact-phash` now says it ignores `--threshold` rather than "faster than general threshold" - the flag groups only distance-0 matches and never consults the threshold, which a reader combining the two would otherwise not discover. README notes that videos need ffmpeg/ffprobe and that an unreadable video is reported with ffmpeg's own reason.
- **0.2.26** fix: two undefined-name crashes, both found by running the real commands on real media. `_prepare_bytes` had lost its `from PIL import Image` when the image branch moved to `load_image_tolerant`, so **every video** failed with `NameError` on `Image.fromarray` — a video library indexed as `analyzed 0, errors 291` after hours spent decoding frames that were then discarded. `find_duplicate_groups` appended to a `groups` list declared further down the function, so `--exact-phash` raised `UnboundLocalError` on every call; its reject list was also sorted by a loop variable leaked from a comprehension, and it fell through to the Hamming pass after grouping, which would have reported the same files twice. Added an AST lint test for undefined names across the package — the bug class that broke both — plus regression tests for staged video indexing and for `--exact-phash`. fix(cli): `_diagnose_failure` ran the *image* diagnosis on any failed path, so a video failing on ffmpeg or on a missing import was reported as "Pillow cannot identify or decode this file": true, useless, and the reason the real error stayed hidden.
- **0.2.25** feat(docs): `media-match help` now groups commands by what they are for instead of listing them alphabetically — get oriented, build the index, go deeper, find things, quality and file management, metadata, index maintenance. An alphabetical list answers "what is this called?"; the grouping answers "what do I want?", and reads in the order you would actually reach for the commands. The README's commands table is grouped to match. `main()` refuses to start if a command is missing from the grouping, listed twice (which is how `check` and `export` were ambiguous in the first draft), or named by a group that does not exist. doc: `about`, `info`, `version` and `restore` were never given a row in the README commands table at all.
- **0.2.24** feat: live progress bar for `scan`/`analyze`/`describe`, replacing the periodic "preparing [n/total]" lines on a terminal. Shows the names of the files in flight, how full the read ring buffer is, CPU-seconds across all threads, and GPU-seconds as a percentage of wall time — enough to tell a slow disk from an idle GPU from a GIL-bound CPU stage without attaching a profiler. Rendered on its own thread at 10 Hz so instrumentation never sits in front of a decode; the pipeline only mutates a small state object under a lock. `--no-progress` (or `MEDIA_MATCH_NO_PROGRESS=1`) disables it; it is off automatically when stderr is not a terminal, so piped output and CI keep one-event-per-line logs. fix(cli): `search --limit` and `tags --limit` had no help text and rendered as a bare "(default: 50)"; `_flag_lines` also produced ragged triple-spaced gaps for help strings ending in a space. fix(pipeline): `run_staged_scan` never incremented `ScanStats.bytes_read` — only the older `run_scan` did — so `stats` had reported `0.0B read` for every scan since the staged pipeline shipped.
- **0.2.23** feat: `about bench` — measures this machine and recommends `--batch`/`--io-workers`/`--workers`. Times disk reads, CPU decoding and CLIP batches in isolation, then runs several real configurations end to end through `run_staged_scan` and reports throughput plus the share of wall time in the GPU, with a projection onto the real tree size. Defaults to a deterministic synthetic corpus (no photos needed, comparable between runs and machines); pass a folder to benchmark real media. Nothing is indexed and no file is touched. The recommendation is deliberately conservative: configurations within the measured run-to-run spread (~10% on a small corpus) are reported as tied and the cheapest of them is recommended, because picking the nominal winner would present a coin flip as a measurement.
- **0.2.22** fix(cli): stop Pillow's warnings reaching the user. Truncated reads, malformed MPO containers and decompression-bomb guard hits printed a `site-packages/PIL/...` path with no filename, once per file — noise in a scan of thousands of files and useless without knowing which file was affected. New `diagnose` module captures them and turns each into a per-file explanation; `scan`/`analyze` now report the filename and what is wrong with it, grouped by cause, with a pointer to `media-match check`. `check` gained a fourth category, `notable` (loads fine, e.g. an MPO read as plain JPEG, or a 121 MP image) — reported but never repaired, so a perfectly good photo is not sent to quarantine. perf(pipeline): three data races in the staged scan that lost or duplicated work silently — every reader thread walked the whole job list (so `--io-workers 4` indexed everything 4×), each reader closed the ring buffer in its own `finally` (so the first to finish closed it under the others), and the GPU loop stopped when readers finished rather than when CPU workers were done (dropping results mid-decode). Termination now keys off per-worker sentinels on the batch queue. fix(pipeline): the staged pipeline decoded images with a bare `Image.open` and silently dropped every truncated file, which the sequential path had always indexed; both now share `load_image_tolerant`.
- **0.2.21** perf(cli): ring-buffer scan pipeline — reader threads fill a bounded ~1 GB `RingBuffer`, CPU workers decode/hash/preprocess, one GPU stage batches CLIP embeddings, one writer stores; disk I/O, CPU and GPU overlap instead of running in sequence (`--io-workers` sizes the reader pool). VLM batching via `Describer.describe_batch()` with `--describe-batch N` (default 1) so captions cost one forward pass per N frames. feat: `bootstrap --move-to DIR` moves non-media files to a folder — keeping their layout, never overwriting an existing file — instead of trashing them. fix(cli): `run_staged_scan` was called but never imported, so every `scan`/`analyze` run raised `NameError`. fix(cli): `analyze`, `describe`, `check`, `reset`, `bootstrap`, `clear-metadata`, `import-metadata` and `export-metadata` were missing from the help registry, so `help <cmd>` answered "Unknown command"; `<cmd> help` treated "help" as the root path and crashed opening a database in a folder that did not exist. feat(cli): `<cmd> --help` now prints the same page as `<cmd> help` and `help <cmd>` — previously it was a bare argparse option dump without the description or example; eleven commands had no description at all and now have one.
- **0.2.20** feat: `analyze` — one integrated pass (scan + describe + refine + classify) over images and videos with a GPU-fed pipeline; `describe` command; `clear-metadata`/`import-metadata`/`export-metadata` round-trip; `reset` command; `check` command (classify ok/truncated/corrupt, interactive repair); `bootstrap` command (dry-run first pass; `--prune`/`--media-only`/`--fix-extensions`); extension consolidation rolled into `bootstrap --media-only`; fix `--describe` without `--model` failing every caption with `Path(None)`; scan tolerates truncated images; periodic MLX cache release on long runs
